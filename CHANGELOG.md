# Changelog

All notable changes to `@isokron/mcp-check` and the `isokron-ai/mcp-check` Action. The package follows [semantic versioning](https://semver.org/); the grading rubric has its own version (`rubric_version`), noted with each release.

## Unreleased

To be released as 1.1.0 (new inputs and a new option, so a minor version; it also carries the changes first planned for 1.0.1, further down). The rubric stays 2.1.0. The engine changes in two heuristics (below); both can only remove advice-level findings. The web checker needs the same two edits to stay in step.

- **Zero-config Action.** With neither `tools-file` nor `command`, the Action reads the tool definitions from the source in `working-directory` and runs nothing. The job summary says so ("Source: repository code; nothing was run"), names how exact the list is, and says how to switch to the live list with `command` or `tools-file`. SARIF results point at the line that registers each tool. When no tool definition is found the job fails with that advice. New output `source` (`repo-static`, `command` or `tools-file`). The smallest workflow is now `actions/checkout` followed by `uses: isokron-ai/mcp-check@v1`.
- **`--repo-dir <path>`**: the `--repo` reading from a local checkout, with no network access. It does not enter `node_modules`, `.git`, virtual environments or caches, does not follow symlinks, keeps `--repo`'s limits (60 source files, 1.5 MiB per file), and reads build output (`dist`, `build`, `out`) and `vendor` only when no source file defines a tool. Exit code 3, with a message naming `--command` and a saved list (`command` and `tools-file` in the Action), when it finds no tool definition. Library: `RepoSource.fromDirectory(path)` beside `fromGitHub`, sharing one scan.
- **The source reader follows same-file helpers** that pass a name and a config on to `registerTool`, such as `function register(server, name, config, fn) { server.registerTool(name, config, wrap(fn)); }`, in `--repo`, `--repo-dir` and the Action. This package's own server registers its tools that way.
- **`publish-hint`** (default `true`): on a public repository on github.com, the job summary ends with a link to the repository's page in the IsoKron MCP registry, where it can be listed for free with its CI-verified grade and a README badge. It is a link only; no request is made. Private repositories, GitHub Enterprise Server and events without a public repository in their payload get no line.
- **`pr-comment`** (`off` by default; `auto` or `always`) and **`github-token`**: one comment per pull request, found again by a hidden marker and updated in place, with the grades, the gate, a high-risk annotation change, the first five findings linked to their check pages, and the registry line. `auto` comments only when a gated section is below `min-grade` or the baseline comparison finds a high-risk change, and then keeps an existing comment current. Pull requests from forks are skipped, with a note in the job summary. The comment is written by its own step, the only one that receives the token (the server `command` starts never has it in its environment); that step reads the pull request from the event payload rather than from the run step's outputs, runs with a clean environment and the `node` found before any repository code ran, and edits only a comment written by the token's own account, so a marker comment by someone else is never taken over. Text from the tool list cannot @mention anyone. A failure to comment is a warning and never fails the job. Needs `permissions: pull-requests: write`. Its links carry the new tag `utm_source=mcp-check-pr-comment&utm_medium=action`.
- **Committed lists in zero-config are labelled, and the baseline is never one.** When the Action grades a committed list (`tools.json`, `tools-list.json`, `mcp-tools.json`, `__toolsnaps__`, `.mcp-catalog/`) instead of code, the job summary says first that it graded that file, not the code, and that it may be stale; SARIF points at the tool's line in it. The `baseline` file is excluded from the scan (and refused if it were chosen), so a change in code is compared with the baseline instead of the baseline with itself. A manifest with names only (no schemas) is not graded in the Action: the job fails and asks for `command` or `tools-file`. A folder over the 20,000-file listing limit is read likely source folders first (`src`, `lib`, `server`, `app`, `packages`, ...), then breadth first, and the summary and the `Source:` line say it was cut. SARIF paths are percent-encoded.
- **mcp-catalog-snap snapshots** (`.mcp-catalog/<server>.json`, written by [mcp-catalog-snap](https://github.com/isokron-ai/mcp-catalog-snap)) are read as an exact committed list by `--repo`, `--repo-dir` and the zero-config Action, and the Action's `baseline` accepts one.
- **`test/`, `tests/` and `__tests__/` are skipped** for committed lists too (source files there were already skipped), in `--repo`, `--repo-dir` and the Action.
- **A server started by `command` (CLI and Action) no longer gets `GITHUB_ENV`, `GITHUB_PATH`, `GITHUB_OUTPUT`, `GITHUB_STATE` or `GITHUB_STEP_SUMMARY`** in its environment.
- **CI**: a `zero-config` job runs the Action with no inputs on this repository, exactly as the docs show.

- **`--repo` reproduces the SDK that the repository pins.** The reader detects the TypeScript SDK line (1.x or 2.x) and the schema library (zod 3 or 4) from the manifests and lockfiles, and the Python SDK or standalone `fastmcp`, and emits what that combination lists: JSON Schema dialect, open or closed objects, integer bounds, titles, `<fn>Arguments` wrappers and `_meta` as the SDK adds them. `execution.taskSupport` is added only for TypeScript SDK 1.24 to 1.x, no longer for every repository. Without detectable SDK information the output has no `execution` field.
- **`--repo` reads more schema forms**: object spreads of local and shared constants, `.shape`, `.optional()` on constants, string and integer constraints in Python annotations and `Field(...)`, docstring `Args:` sections, and placeholders for properties it cannot read instead of dropping them.
- **`--repo` leaves out tools that the server would not list.** A tool is set aside when a literal table disables it, when it declares run-time conditions, when it exists only in one of several alternative server modules, or when it is a declaration that nothing registers; tools registered under a condition that cannot be decided from source are kept and marked. The `Source:` line says how many were left out, why, and how many were kept under a condition. If every tool would be left out, none is.
- **Engine**: `annot-write-marked-readonly` treats `open_` followed by an existing object (`open_nodes`, `open_file`) as a read; `open_pull_request` and `open_issue` still create. `surface-full-replace` no longer counts `move_`, `rename_`, `assign_`, `unassign_`, `transition_`, `merge_`, `restore_` and `sync_` as replacing a whole object when all their arguments are required, since those take two operands or one state change. Tests in `test/calibration.test.cjs`.
- **Tests**: `test/repo-reader.test.mjs` covers the reader on synthetic repositories; `test/checks.test.cjs` already pins that a live answer without `resultType`, `ttlMs` and `cacheScope` is `advice` for a 2025-11-25 era server and `attention` only when the answer carries 2026-07-28 fields.

- **Channel tags on links to isokron.ai.** The links this package prints or writes for a person to open now carry a fixed `utm_source` and `utm_medium` naming the place they appear: `mcp-check-cli` (`--help` and the text report), `mcp-check-action` (the job summary), `mcp-check-badge` (the `report.md` committed beside `badge.json`), `mcp-check-sarif` (`informationUri` and each rule's `helpUri`), `mcp-check-server` (the MCP server's `websiteUrl`), `mcp-check-npm` (the package's `homepage`), `mcp-check-registry` (`websiteUrl` in `server.json`) and `mcp-check-readme` (the README and this file). A tag names the surface and carries nothing about the reader, the server or the run. Not tagged: the `docs` values in JSON reports and in the MCP server's tool results, the Markdown and JSON exports, and the web-checker link that carries a tool list in its fragment. New module `src/links.js`; `test/link-tags.test.mjs` fails when a link lacks its tag or uses an unknown source.
- **Docs**: the README's option table lists `-v, --version` and `-h, --help`, and says that `-o` sends the text summary to stderr only for a format other than `text`. `test/docs.test.mjs` checks the Action's inputs, outputs and defaults in `docs/github-action.md` against `action.yml`, and the options, exit codes, sections and limits in the README against the command line.

## 1.0.0 (2026-11-19)

Rubric 2.1.0, MCP specification 2026-07-28, directory rules as read on 18 November 2026.

First public release: the engine of the [isokron.ai/mcp-check](https://isokron.ai/mcp-check?utm_source=mcp-check-readme&utm_medium=readme) web checker as a package, a command line, an MCP server and a GitHub Action, at one version.

- **Engine**: 76 checks with stable IDs in six sections (MCP spec, Anthropic directory, OpenAI directory, poisoning and hidden text, schema and description quality, write-surface design), each with its source quoted verbatim, an explanation and a fix. Per-section grades A to F from severity-weighted deductions with published bands and caps ([RUBRIC.md](RUBRIC.md)). JSON Schema 2020-12 validation with the bundled Ajv 8.17.1. Safe-fix list, SHA-256 definition hashes and a diff that flags high-risk annotation changes.
- **CLI** (`mcp-check`): text, Markdown, JSON and SARIF output; `--min-grade`, `--sections`, `--fix`, `--compare`, `--stdin`, `--sarif-uri`, `-o`. `mcp-check serve` runs the MCP server.
- **Inputs**: `--url` (Streamable HTTP, 2026-07-28 stateless and the earlier handshake, SSE, paging; `--header` values read from the environment and never printed), `-- <command>` / `--command` (stdio), `--config auto|<file>` (Claude Desktop, Claude Code, Cursor, Windsurf, VS Code JSONC, Zed), `--repo` (static extraction with a provenance label), `--registry`, `--save`, a `Source:` line on every report, exit code 3 when a server cannot be reached. Every path sends `initialize` and `tools/list` only and keeps the size, page, time and output limits.
- **MCP server** (`mcp-check serve`, `mcp-check-server`): `check_tools_list`, `explain_check`, `compare_tools_lists`, all read-only with output schemas; input limits of 2 MiB, 64 levels and 2,000 tools. Grades A in every graded section against itself. Registry name `io.github.isokron-ai/mcp-check`.
- **GitHub Action** (`isokron-ai/mcp-check@v1`): a tool-list file or a server command; job summary with the grade table; reports artifact; SARIF with file locations and optional code-scanning upload; minimum-grade gate; baseline comparison; README badge as a shields.io endpoint file committed to the user's repository.
- **Hardening**: job-summary text from the list or the server is escaped so it cannot form links, images or HTML; the Action never reads or writes through a symlink and writes only into a results folder it made; the server's stderr is fenced with `::stop-commands::`; the 2 MiB, 64-level and 2,000-tool limits apply in the CLI and the Action too.
